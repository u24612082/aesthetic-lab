# Metrics, provenance and coaching

- Dates use `Africa/Johannesburg`; timestamps are stored in UTC with source offsets validated.
- Direct sets count non-warmup sets, not inferred muscle activation. Known hard sets require RIR ≤4; unknown RIR stays unknown. Secondary sets appear separately and are not silently counted as equivalent direct sets. These are configurable heuristics, not physiological measurements.
- Tonnage is reported load × reps, with no automatic unilateral or dumbbell doubling. Adapters must use a consistent load convention. Record distinct equipment IDs and resistance modes; changing apparatus breaks comparable load progression.
- The Epley estimate flags ≥5% declines between the latest two sessions of the same exercise/side/equipment/mode with reps ≤12 and RIR ≤2. Bodyweight/zero-load sets are excluded. This prompts a review; it cannot diagnose fatigue. Repeated comparable sessions and broader context are needed.
- Left/right gaps compare the best near-failure Epley estimates within one session, movement, apparatus and mode. This does not measure muscle size, visual symmetry or a verified strength deficit. No side is inferred from a bilateral score.
- Food totals use grams / 100 × stored nutrients and are snapshotted at logging time. Catalogue edits affect future entries. Raw/dry/cooked bases must match. The requested retail catalogue is seeded with **illustrative values**, not verified current product nutrition. SASKO oats is an explicitly unverified requested brand/product pairing. No invented barcodes are seeded. Check each package before precision use.
- Nutrition uses a single downloaded-library/product/barcode search. Explicit Search all queries Open Food Facts globally with cc=za context, prioritizing South African products. Known kJ values are converted to kcal, incomplete macro records are excluded, and source provenance remains visible. See [food and rest](food-and-rest.md). Open Food Facts records retain their [ODbL terms](https://world.openfoodfacts.org/terms-of-use), separately from the combined application's AGPL licence.
- Recorded body weights from Stats enter the analysis and both coach contexts, with weekly means and date-aware scale trends. No body composition is inferred. The optional [adaptive macro planner](adaptive-nutrition.md) provides phase-aware targets and evidence-gated, audited changes. Unlogged or partial food days remain unknown intake.

## Technique-gated progression

Inspired by [ANPC86/claude-smart-gym-coach](https://github.com/ANPC86/claude-smart-gym-coach), inspected at commit `234715b8cc011e9d90a7297f741f8adcfc341029`. Original implementation here; no Notion dependency. The reference's [session-review rules](https://github.com/ANPC86/claude-smart-gym-coach/blob/main/smart-gym-session-review-SKILL.md) use amplitude and force-control scores before load progression.

The deterministic local gate requires **both amplitude stability and force control ≥3/5 for isolation and ≥4/5 for compounds**, on **every working set of the latest session** for each movement/apparatus/mode/side. A low score holds load. Missing measured scores or unverified movement/equipment/mode/side means insufficient evidence, also preventing eligibility. Warmups are excluded. A newer unscored session supersedes an older pass.

Known bilateral balance below 3/5 adds a hold. A zero bilateral score on a unilateral movement is treated as a device artifact, not a balance failure. Completion score is stored for review but does not replace amplitude or force control. The client cannot declare itself an isolation exercise to lower a threshold; classification comes from the reviewed server mapping. User-specific mobility exceptions from the reference repository are **not** applied to a different athlete automatically.

These scores must originate from an actual measuring device or authorized technique integration, identified by `evidence_source`. Neither HealthKit summaries nor ordinary Liftoff weight/repetition logs guarantee these measurements. Authentication establishes the trusted importer; the server does not independently verify sensor calibration or source claims. Missing scores are not generated by Claude, inferred from RIR, or requested through manual workout input.

**Passed** means technique prerequisites permit review; it is not an approved load increment. Rep targets and individual progression context are currently absent, so the coach withholds specific weight increases. This rule cannot guarantee injury prevention or mechanical tension. It prevents the software from treating a rep/load PR as proof of good technique.

## Claude audit

The personal installation uses the official Claude Code client and its existing Claude Pro subscription login, automatically in the background. There is no routine Terminal/prompt step or API-token fallback. See [Claude Pro operation](claude-pro.md). The iPhone can request and read a fresh review when the Mac is reachable; offline it displays the last downloaded review. Fresh inference runs on the Mac within the subscription allowance.

`claude_analyser.py` retains an optional, separate Anthropic API SDK path for installations that explicitly configure API billing, and deterministic local reports when no model is used. Hosted generation through that module is disabled when COACH_PROVIDER=subscription. All coaching receives weight and configured nutrition-plan context, respects missing/partial evidence and technique holds, and cannot independently edit the programme or the macro controller's targets.

Structured tool output is validated with Pydantic; set adjustments are restricted to mapped targets and ±4 per target per week, and suggestions are removed when fewer than three detailed sessions or ten mapped known-hard sets exist. Auth, model, network, billing/request and rate-limit errors are translated into messages in the coach panel and connection log, without exposing provider response bodies or credentials. Failed generation preserves the previous report and imposes a one-minute retry cooldown. Reports are advisory; they never change training records or a programme.

Demo mode disables hosted AI and credential changes, and never consumes the real iCloud inbox. All new hosted-generation tests use a mocked provider; no live Claude generation has been verified without the user's API key.

The audit covers 28 days independently of the overview filter and may lag recent input by the cooldown. Local rules and AI use the same deterministic technique gates; the visible gate is always computed from current data even if the saved narrative is older.
